NuclaDB is a vector similarity search engine written from scratch in Go. The server, `nucladbd`, runs the HNSW graph, the crash-safe WAL, mmap snapshots, multi-tenancy, metadata filters, API keys and TLS, and a gRPC + REST API. Product quantization and a Raft-coordinated sharded cluster are also implemented and tested as Go packages, but the server doesn't run them yet. All of it is implemented directly in this repo, not imported from another engine.

<Callout type="info" title="Why this exists">
  Most "vector database" side projects wrap an existing engine (Qdrant, Pinecone, pgvector) behind an app. NuclaDB is the other direction: it implements the kind of internals those engines are built from, and is benchmarked head-to-head against a real Qdrant instance instead of assumed to be competitive.
</Callout>

## Known limitations

A few things are worth knowing up front, so nothing here reads as more finished than it is:

- Qdrant's recall is a little higher at low `ef` (0.959 vs 0.932 at ef=10), though NuclaDB is faster at every `ef` tested. See [HNSW ef tuning](/docs/design-decisions/hnsw-ef-tuning).
- Product quantization and the sharded cluster are libraries, not server modes: `nucladbd` runs a single node without PQ. Nothing yet starts replication streams per shard or moves data on a rebalance. See [Distributed cluster](/docs/distributed).
- Flat product quantization gets 57.7% recall@10 at 16x compression; re-ranking the top 100 brings it to 99.3%. See [Product quantization cost](/docs/design-decisions/product-quantization-cost).
- A 4-shard cluster runs 38 to 45% slower (in QPS) than single-node, from scatter-gather network hops. See [What Raft gave and cost](/docs/design-decisions/what-raft-gave-and-cost).
- Replication is async, so a leader failover can lose an acknowledged write. The Jepsen-style tests report this rather than hide it.

The numbers in these docs come directly from committed benchmark output (`bench/results.md`, `bench/results-cluster.md`) or from the Go source itself. None of it is estimated.
